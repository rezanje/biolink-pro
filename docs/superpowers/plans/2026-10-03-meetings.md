# Conversation history and meeting approval Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Read full visitor conversations and request meetings that enter the owner's Google Calendar only after approval.

**Architecture:** Reuse the existing concierge message table with paginated, owner-scoped reads. Add service-only Calendar credentials and owner-readable booking requests, with server routes handling OAuth, slots, and atomic approval transitions. Keep external setup visible and separately verifiable.

**Tech Stack:** Next.js 16, React 19, Supabase, Google Calendar REST, Node crypto, existing node:test and browser fixtures.

**Spec:** docs/superpowers/specs/2026-10-03-meetings-design.md

## Global Constraints

- No new runtime dependencies or live Calendar writes in tests.
- Premium/B2B only; events/invitations only after owner approval.
- Primary calendar; 15/30/60 minute meetings; 14 days ahead; two-hour notice; IANA timezone.
- Never return OAuth tokens or private event titles to a client.

## Review Focus

- Older messages and same-timestamp question/reply pairs must be ordered and selectable independently.
- Timezone and DST boundaries must produce valid local business-hour slots.
- OAuth denial, missing refresh token, or cross-owner state must not link an account.
- Concurrent approval or retry must not create duplicate events or approve a rejected request.
- Missing operator setup, lost permissions, or a busy slot must produce useful, retryable UI.
